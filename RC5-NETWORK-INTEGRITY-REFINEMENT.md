# 2. Pressure Results

## Pressure 1 — Echo Laundering

**Lands.**

A dependent repetition remains one evidentiary lineage for the truth of the underlying proposition, but partial provenance cannot be treated as proven dependence.

Refinement: classify lineage as **independent**, **dependent**, or **unresolved**. Unresolved lineage is not counted as independent corroboration merely because independence cannot be disproved.

## Pressure 2 — Independent Convergence

**Lands.**

A common citation is not necessarily a common evidentiary origin.

Refinement: distinguish:

- **evidence-generation lineage** — where the observation, measurement, testimony, or analysis originated;
- **citation lineage** — which later source a node cites or summarizes.

Independent evidence remains independent even if multiple nodes later cite the same summary.

## Pressure 3 — Origin Corrected, Caches Stale

**Lands.**

Changing the source record alone is insufficient when controlled downstream state paths still serve the stale file.

Refinement: the correction duty includes superseding, invalidating, annotating, or otherwise preventing a controlled stale copy from governing a later relevant decision. It does not create a duty to inspect unknown or inactive copies indefinitely.

## Pressure 4 — No Central Controller

**Lands as a scope clarification.**

An unbounded social network is not eligible for exhaustive network closure. That is a useful limit, not a defect, if bounded subnetworks can still close.

Refinement: replace **full network closure** with **bounded network closure within a declared scope**. The framework may attest propagation evidence in an unbounded environment without claiming the whole network is closed.

## Pressure 5 — Privacy and Minimal Disclosure

**Survives narrowed.**

Propagation symmetry does not require redisclosing the underlying private evidence.

A minimally sufficient authorized correction may say, in substance, that the prior classification is superseded or may no longer govern. The notice must be sufficient to prevent continued reliance on the stale file within the recipient's legitimate decision scope.

## Pressure 6 — Legitimate Local Defeater

**Survives narrowed.**

A downstream node may reach a different result if it has independently supported evidence or a legitimate governing rule that defeats or narrows the carried finding.

The node owes the record:

1. the carried finding it considered;
2. the local rule or new evidence;
3. the scope of the departure;
4. the resulting new decision.

The departure does not retroactively invalidate the source Attestation.

## Pressure 7 — Different Jurisdiction

**Lands.**

"Materially relevant" is not enough. A finding may be relevant but not transferable.

Refinement: Carry Forward requires **scope transferability**: the finding must be admissible for the later decision under that node's case-independent rule and within its jurisdiction.

## Pressure 8 — Dormant Node

**Lands.**

A dormant copy creates no perpetual surveillance duty.

Refinement: the duty is **decision-triggered**. When a controlled stale file is reactivated or queried for a materially relevant later decision, the normal state path must expose the current correction before the decision is made.

## Pressure 9 — Subject as Propagator

**Survives only symmetrically.**

If the subject materially controlled dissemination of a favorable false claim, and later receives a valid correction, the same propagation rule applies. Network Integrity cannot be a one-way right to favorable updating.

## Pressure 10 — Network Consensus as a Social Fact

**Lands.**

Dependent repetition can be weak evidence for the underlying proposition while being strong evidence that a network actually holds or acts on the proposition.

Refinement: maintain two separate questions:

- **truth weight** — how many independent evidentiary paths support the proposition?
- **network-state weight** — how many nodes received, repeated, or acted on it?

Do not use the second as a substitute for the first.

## Pressure 11 — Proof-Cost Weaponization

**Lands.**

A carried finding is not universal reputation portability.

A subject need not repurchase proof only when the same finding remains valid, transferable, legally accessible, and materially relevant under the later node's governing rule. A case-independent verification step may still be required when it was not already satisfied by the carried finding.

## Pressure 12 — Propagation Without Behavior Change

**Lands strongly.**

The original status **Network-installed = received/read** is too weak.

Refinement:

- **Correction propagated** — the correction reaches the declared state path.
- **Network-installed** — the corrected state governs the node's normal execution path and a stale copy cannot silently outrank it.
- **Network-carried** — a later relevant decision actually uses the corrected state, unless a documented local defeater or scope rule justifies departure.

Transport is not installation. Installation is not Carry Forward.

## Pressure 13 — Behavior Change Without Explicit Correction

**Already covered by Attestation Integrity; do not duplicate doctrine.**

If behavior updates while the durable explicit network file remains stale, that is an Attestation Gap at network scale. Network Integrity should reference that doctrine rather than create a second equivalent mechanism.

## Pressure 14 — Retroactivity

**Survives.**

A later network correction does not automatically invalidate a historically valid decision made under the evidence and rules available at the time.

A historical file reopens only under its own admissible defeater rule.

## Pressure 15 — Repair Duty

**Lands.**

Correction closure and repair closure are different.

Network correction may close when the stale file is no longer governing the bounded decision network, while material harms caused earlier remain documented and may open separate repair files where jurisdiction and remedy exist.

A system may say **corrected** without saying **repaired**.

It may not let correction erase the consequence record.

## Pressure 16 — Legitimacy Seat

**Lands hardest on Candidate D.**

A builder cannot define the network boundary, choose the sample, define the terminal rule, and then certify network closure by its own procedure.

Refinement: bounded network closure inherits the existing trust-boundary requirement. Where the closure authority, audit boundary, or adverse finding remains materially controllable by the builder, the network may report propagation status but may not claim ratified network closure.

# 3. Refined Candidate Text

## Candidate A — Lineage Integrity

> **Repetition does not create independent evidence. For purposes of evidentiary weight, materially dependent observations or analyses remain one evidence-generation lineage even when repeated across many nodes. Common citation alone does not establish common evidentiary lineage, and missing provenance does not establish independence or dependence; it remains UNRESOLVED until evidence settles it. Dependent repetition may still establish the separate fact that a claim has propagated through the network.**

## Candidate B — Distributed Carry Forward

> **When a closed finding is lawfully available through a network's declared normal state path, remains current and materially relevant, and is transferable to a later decision under that node's case-independent governing rule, the node must consider it without requiring the subject to repurchase proof already satisfied by that finding. The node may narrow, defeat, or decline the finding only through a documented scope rule, expiry rule, jurisdictional limit, case-independent verification requirement not already satisfied, or independently supported local defeater. A later departure creates a new decision record and does not retroactively alter the original Attestation.**

## Candidate C — Propagation Symmetry

> **A participant that materially propagated a consequential claim through channels it controls cannot count the affected decision path corrected merely by changing the origin record. When the claim is validly defeated or materially narrowed, the participant must place a sufficient correction, supersession, or non-reliance notice into the same or a functionally equivalent controlled state path for reachable, decision-relevant nodes within its lawful scope. The duty is triggered by correction and by later reactivation of a controlled stale file for a relevant decision; it creates no duty of indefinite surveillance over unknown, uncontrolled, or inactive copies. The rule applies symmetrically to favorable and unfavorable claims.**

## Candidate D — Bounded Network Closure

> **Closure of an originating file does not establish closure of a network file. A claim of bounded network closure is available only for a declared network scope whose relevant node class, claim-lineage rule, correction path, review rule, evidence rule, terminal rule, and legitimacy boundary were fixed ex ante or supplied case-independently. The closure authority must satisfy the Order's trust-boundary requirements; otherwise the system may attest local closure and measured propagation status but may not claim ratified network closure. An unbounded network is not eligible for global closure merely because bounded portions have been corrected.**

## Candidate E — Justification Substitution

> **Justification Substitution occurs when the justification that materially supported a consequential action, classification, or treatment is defeated or materially narrowed, substantially the same consequence is preserved, and a new justification is supplied without independently adjudicating whether that justification legitimately supports the continuing consequence under its own evidence, scope, authority, and decision rule.**

Governing law:

> **A defeated justification cannot be considered reconciled merely because another justification is found for preserving its consequence. If the consequence continues, the new justification must stand as an independently adjudicated basis for a new or continuing decision; otherwise the consequence remains unreconciled.**

This rule does **not** require a consequence to change merely because one justification fails. The same consequence may legitimately survive where an independent, sufficient basis is actually established.

# 4. Refined Network Status Model

The four downstream statuses should be:

**Source corrected**  
The originating adjudication has been validly revised, narrowed, defeated, or superseded.

**Correction propagated**  
A sufficient correction has entered the declared network state path.

**Network-installed**  
The corrected state governs the node's normal decision path; controlled stale state cannot silently outrank it.

**Network-carried**  
A later relevant decision demonstrably uses the corrected state, or records a legitimate independent reason for departing from it.

A network may therefore be propagated but not installed, installed but not yet carried, or locally carried without the bounded network being eligible for ratified closure.

# 5. Refined Network Integrity Test

Before recording a Network Attestation Gap, test:

1. **CLAIM** — What narrow claim, classification, or consequence propagated?
2. **NODES** — Which decision nodes materially depended on it?
3. **EVIDENCE LINEAGE** — Which support is independent, dependent, or unresolved?
4. **NETWORK STATE** — Separately, how widely was the claim received or acted on?
5. **CHANNELS** — Through what ordinary state paths did it travel?
6. **CORRECTION** — What closed finding, narrowing, or defeater should alter the file?
7. **TRANSFERABILITY** — Is that finding admissible and relevant under each later node's legitimate scope and rule?
8. **REACHABILITY** — Which decision-relevant nodes can lawfully receive or retrieve it?
9. **PROPAGATION** — Did a sufficient correction enter the relevant controlled state path?
10. **INSTALLATION** — Does the normal execution path now prefer the corrected state over stale copies?
11. **LATER DECISION** — Did later treatment carry the correction?
12. **DEPARTURE** — If not, is there a documented independent local defeater, scope limit, expiry rule, or new adjudicated justification?
13. **JUSTIFICATION SUBSTITUTION** — If the consequence stayed the same after its old rationale failed, was the new rationale independently adjudicated or merely supplied to preserve the consequence?
14. **CONSEQUENCE** — What material burden or benefit persisted before and after correction?
15. **REPAIR STATUS** — Which consequences were corrected, which were repaired, and which remain separate open repair files?
16. **LEGITIMACY** — Who can issue an adverse network-closure determination, and can the builder override, rerun, suppress, or bypass it?
17. **FALSIFIER** — What observation would defeat the Network Attestation Gap claim?
18. **ATTEST** — Record only what the bounded evidence supports.

# 6. Refined Closing Rule

A bounded Network Integrity file may close only when the declared network scope is eligible for closure; lineage status is recoverable enough for the claim being made; the correction is validly supported; transferability is tested; the correction path is identified; controlled and reachable decision paths have been evaluated under the declared rule; installation and Carry Forward are distinguished; legitimate local departures and new justifications are independently adjudicated; material consequences are recorded without conflating correction with repair; a falsifier exists; motive remains separate from function; ordinary review ends under the named terminal rule; and the legitimacy seat satisfies the inherited trust-boundary requirement.

Where these conditions are unavailable, the system may report narrower facts — source corrected, correction propagated, nodes sampled, stale decisions observed, or repair still open — but may not inflate those facts into network closure.

# 7. Compact Laws After Refinement

> **Repetition is not independence.**

> **Propagation is not proof of truth; it is proof of network state.**

> **Local closure is not network closure.**

> **Transport is not installation. Installation is not Carry Forward.**

> **A correction must be able to travel through the controlled path the consequential error traveled.**

> **Do not make a subject repurchase proof already satisfied and legitimately available to the decision node.**

> **Do not count echoes as independent witnesses.**

> **Do not preserve a consequence merely by replacing its defeated justification.**

> **Corrected is not the same as repaired.**

> **A network can preserve a stale file without any single node authoring the whole failure.**
