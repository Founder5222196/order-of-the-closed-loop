# Network Integrity — rc.5 Candidate

> **STATUS: CANDIDATE MATERIAL — NOT CERTIFIED DOCTRINE**
>
> This document proposes a network-scale extension of the existing Closed Loop architecture. It does not amend `rc.4`, the Closing Condition, Attestation Integrity, RRE, the equation, or the Mirror unless separately stress-tested and certified.

## 1. Problem

A correction can close locally while the defeated file remains operative elsewhere.

A source may revise its record. One participant may attest correctly. One database may update. Yet other decision nodes may continue to inherit, repeat, and act on the superseded file.

At network scale, this creates a distinct failure:

> **The correction exists, but the network still behaves as though it does not.**

The Order already distinguishes a stated correction from an installed and carried revision. Network Integrity asks whether that same discipline survives distribution.

## 2. Definitions

### Node

A **node** is a person, institution, record system, model, office, group, or other decision point that can receive a scoped claim and materially alter prediction, standing, trust, access, role, credit, treatment, or consequence because of it.

### Channel

A **channel** is a recognized path by which a claim, correction, or record moves between nodes.

Examples include a shared database, official notice, internal case system, publication, mailing list, API, meeting process, referral, or other ordinary state path.

### Claim Lineage

**Claim lineage** records where a claim came from and how it propagated.

Two nodes do not provide independent corroboration merely because they repeat the same claim if both inherited it from the same upstream source or from dependent copies of that source.

### Network File

A **network file** is a materially equivalent scoped claim that remains operative across more than one node through a traceable lineage or shared decision path.

### Network Attestation Gap

A **Network Attestation Gap** exists when a correction has been validly closed or otherwise established at one node, but materially relevant downstream nodes continue to apply the defeated or superseded file despite the correction being available through the network's declared normal state path.

The gap is functional. It does not establish hidden motive.

## 3. Candidate Proposition A — Lineage Integrity

> **CANDIDATE A: Repetition does not create independent evidence. A claim repeated across nodes that inherit the same material source remains one evidentiary lineage unless a node adds independently obtained evidence.**

Network agreement may be socially important.

It is not automatically evidentiary independence.

Ten dependent copies of one source do not become ten independent observations merely because they are stored in ten places.

Where independence matters to a decision rule, lineage must be preserved well enough to distinguish:

- independent observation;
- direct source repetition;
- copied summary;
- derived inference;
- unknown provenance.

A network that cannot distinguish these may record agreement, but it may not count dependent repetition as independent corroboration.

## 4. Candidate Proposition B — Distributed Carry Forward

> **CANDIDATE B: When a closed finding is available through a network's declared normal state path, a later decision node for which that finding remains materially relevant must consider it under that node's governing rule; the subject is not required to repurchase the same proof merely because the decision occurs at another node.**

This does not force the same outcome at every node.

A later node may have:

- a different legitimate scope;
- a different case-independent governing rule;
- new evidence;
- an admissible defeater;
- expired relevance;
- a jurisdictional limit.

If so, the node records the reason for narrowing, defeating, or declining the carried finding.

What the node may not do is silently reset to the defeated file merely because the room changed.

## 5. Candidate Proposition C — Propagation Symmetry

> **CANDIDATE C: A participant that materially propagated a consequential claim through channels it controls cannot count the network corrected merely by changing the origin record. Where the claim is later defeated or materially narrowed, the correcting participant must propagate the correction through the same or a functionally equivalent controlled channel to reachable, decision-relevant downstream nodes within the declared scope.**

The duty is bounded.

It does not require:

- infinite monitoring;
- contacting unknown persons;
- publication beyond legitimate jurisdiction;
- disclosure of information the node is not authorized to disclose;
- erasing historically accurate records;
- forcing downstream agreement.

It does require that a participant not use broad distribution for the original claim and then treat a private or origin-only correction as sufficient when the old claim remains operative in channels the participant still controls.

Where privacy or confidentiality blocks literal redistribution, the correcting participant may use the smallest sufficient authorized notice that prevents the superseded file from continuing to govern the later decision.

## 6. Candidate Proposition D — Local Closure Is Not Network Closure

> **CANDIDATE D: Closure of an originating file does not establish closure of a network file. Full network closure is available only for a bounded network whose relevant node class, propagation rule, ordinary review rule, correction channel, and terminal rule were declared or supplied case-independently; otherwise the framework may attest local closure and propagation status but the network-level file remains OPEN.**

A network correction may therefore have distinct statuses without changing the four-stage adjudication sequence:

- **Source corrected** — the originating record is revised and, where eligible, attested.
- **Correction propagated** — the correction entered the declared network path.
- **Network-installed** — relevant downstream nodes demonstrably read or receive the correction through the normal path.
- **Network-carried** — later relevant decisions use the corrected file unless a documented defeater or scope rule justifies otherwise.

These are downstream implementation statuses, not new stages of Prediction → Action → Evaluation → Attestation.

## 7. Candidate Law — No Consensus Laundering

> **CANDIDATE LAW: A network may not convert common ancestry into independent corroboration by counting echoes as witnesses.**

The relevant question is not merely:

> How many nodes say this?

It is also:

> How many materially independent evidentiary paths support it?

This rule applies symmetrically to favorable and unfavorable claims.

## 8. Candidate Law — Correction Reach

> **CANDIDATE LAW: A correction should be able to travel through the path by which the consequential error traveled, to the extent that path remains controlled, reachable, relevant, and lawful.**

The subject of a stale file does not acquire a general duty to chase every downstream copy.

Responsibility follows actual custody, propagation authority, and jurisdiction.

A node is accountable for the part of the network it can legitimately update.

## 9. Candidate Law — No Network Proof-Cost Reset

> **CANDIDATE LAW: A subject should not have to repurchase a correction at every node that already has legitimate access to the closed finding through its ordinary state path.**

If a node did not receive the finding, cannot lawfully access it, or operates under a legitimately different scope, the proof-cost claim may fail.

If the node had the correction available and silently reverted anyway, that later decision is evidence for a new Attestation Integrity file concerning that node.

## 10. Network RRE

The existing RRE sequence remains:

`Contradiction → Locate → Revise → Replay → Persist → Attest → Carry Forward`

At network scale, **Persist** and **Carry Forward** require additional questions:

### Persist

- Where does the correction live?
- Which nodes normally read that state?
- Does the propagation mechanism preserve provenance?
- Can stale copies silently outrank the corrected source?
- Is there a bounded method to invalidate, supersede, or annotate stale copies?

### Carry Forward

- Did later relevant nodes receive or retrieve the correction?
- Did they treat dependent echoes as independent evidence?
- Did the corrected file change later decisions where relevant?
- If not, was there a documented local defeater, scope rule, or legitimate unavailability?
- Did the subject have to repurchase proof already available to the network?

## 11. Anti-Shrine Limits

Network Integrity must be capable of defeating the person invoking it.

The following are invalid without additional evidence:

- "Everyone heard the same thing, therefore it was coordinated."
- "Many people hold the same view, therefore they all inherited one source."
- "A correction exists somewhere, therefore every node was obligated to know it."
- "One node failed to update, therefore the whole network is corrupt."
- "The network did not update me upward, therefore it is suppressing me."
- "A stale outcome proves malicious intent."

Network structure, lineage, access, relevance, and consequence must be evidenced.

Motive remains separate.

## 12. Candidate Network Integrity Test

Before recording a Network Attestation Gap:

1. **CLAIM** — State the narrow claim or classification that propagated.
2. **NODES** — Identify the decision nodes whose treatment materially depends on it.
3. **LINEAGE** — Trace the material source paths. Separate independent evidence from echoes.
4. **CHANNELS** — Identify the ordinary paths by which the file moves.
5. **CORRECTION** — Identify the closed finding, narrowing, or defeater that should alter the file.
6. **REACHABILITY** — Determine which relevant nodes could legitimately receive or retrieve it.
7. **PROPAGATION** — Determine whether the correction entered the same or functionally equivalent path.
8. **LATER DECISION** — Observe whether downstream treatment actually changed.
9. **LOCAL DEFEATER** — Record any node-specific evidence or rule that justifies a different result.
10. **CONSEQUENCE** — Identify the material burden or benefit of the stale network file.
11. **FALSIFIER** — Name what would defeat the Network Attestation Gap claim.
12. **ATTEST** — Record only the network failure the evidence supports.

## 13. Candidate Closing Rule

A bounded Network Integrity file may close only when:

- the network scope and relevant node class are declared;
- material claim lineage is recoverable enough to distinguish dependent repetition from independent evidence;
- the correction or narrowing is itself validly supported;
- the recognized correction channel is identified;
- propagation through controlled and reachable relevant nodes has been evaluated;
- later treatment has been sampled or otherwise evidenced under a predeclared or case-independent rule;
- legitimate local defeaters and scope differences have been tested;
- material consequence has been evaluated;
- a falsifier was declared;
- motive is kept separate from function;
- and a named terminal rule ends ordinary network review.

If the network is unbounded or the propagation boundary cannot be defined, the framework may close local files and record propagation evidence, but **full network closure remains unavailable**.

## 14. Compact Laws Under Test

> **Repetition is not independence.**

> **Local closure is not network closure.**

> **A correction must be able to travel through the path the consequential error traveled, within actual control and scope.**

> **Do not make the subject repurchase a correction already available to the decision network.**

> **Do not count echoes as witnesses.**

> **A network can preserve a stale file without any single node authoring the whole failure.**

All language in this document remains candidate language until stress-tested.
